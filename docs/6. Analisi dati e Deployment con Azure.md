# Analisi dei dati e Integrazione dell'AI
---
>Il presente documento descrive l'utilizzo degli strumenti di supporto basati su intelligenza artificiale durante lo sviluppo della piattaforma PostIn, illustrando gli ambiti di intervento, le scelte metodologiche e il processo di validazione del codice.
---
## Integrazione di strumenti di Intelligenza Artificiale

1. **Funzionalità applicativa:** Integrazione dei servizi cognitivi cloud di **Azure AI** per l'elaborazione del linguaggio naturale (NLP = _Natural Language Processing_) e la classificazione del sentiment dei commenti generati dagli utenti.
2. **Supporto allo sviluppo e refactoring:** Adozione di modelli linguistici avanzati per l'analisi della concorrenza del codice asincrono, la diagnosi dell'esplosione cartesiana nelle query EF Core, l'implementazione del pattern `IDbContextFactory` e la revisione critica della codebase.

## Problemi Rilevati

Durante l'evoluzione e i test di carico dell'applicazione sono emerse due criticità architetturali collegate:
**A. Concorrenza su `DbContext` e Crash al Cambio Pagina**
- **Problema:** Quando un utente avviava una query complessa e cambiava pagina prima del completamento, l'applicazione generava un'eccezione non gestita:

$$\text{System.InvalidOperationException: A second operation was started on this context instance...}$$

- **Causa:** In Blazor Server, il ciclo di vita del circuito SignalR associa le dipendenze registrate come `Scoped` (incluso `DbContext`) all'intera sessione dell'utente. Poiché `DbContext` non è thread-safe, la navigazione lanciava una nuova query sul medesimo contesto mentre la query precedente era ancora attiva sul canale asincrono.

**B. Esplosione Cartesiana e Latenza di Rete**
- **Problema:** Il caricamento di pagine contenenti liste estese (es. pannello Admin) causava blocchi di svariati secondi e saturazione della banda.
- **Causa:** L'uso cumulativo di molteplici clausole `.Include()` su collezioni 1-a-Molti collegate a oltre 20.000 record (es. Commenti, Like, Visualizzazioni) generava un'esplosione cartesiana a livello SQL ($M \times N \times P$ tuple duplicate scaricate dal cloud).

---
## Soluzioni Architetturali Implementate

**1. Adozione del Pattern `IDbContextFactory<ApplicationDbContext>`**

Tutte le pagine Razor hanno subito un refactoring per non dipendere più da un'istanza `Scoped` iniettata direttamente, ma dalla factory thread-safe:

```
@inject IDbContextFactory<ApplicationDbContext> DbFactory

// In ogni operazione asincrona:
using var context = await DbFactory.CreateDbContextAsync(cts.Token);
```

In questo modo ogni operazione ottiene un contesto isolato a vita breve, eliminando i conflitti di concorrenza tra componenti o tra cambi di rotta.

**2. Gestione del Ciclo di Vita e `CancellationTokenSource`**

Ogni pagina implementa l'interfaccia `IDisposable`. All'avvio del caricamento viene generato un token di cancellazione; se l'utente naviga altrove, il metodo `Dispose()` attiva la cancellazione immediata della query pendente sul database:

```
public void Dispose()
{
    cts.Cancel();
    cts.Dispose();
}
```

**3. Proiezioni DTO/ViewModel Server-Side**

Nel pannello di amministrazione (`AdminPosts.razor`), il caricamento di collezioni massive è stato sostituito da una query di proiezione con `.Select()`:

- Il database esegue i conteggi nativamente tramite `COUNT()` su SQL Server.
- Vengono trasferiti solo i valori scalari aggregati (`LikesCount`, `CommentiCount`, `VisualizzazioniCount`), azzerando l'overhead di memoria e la latenza di rete.

## Dataset, Seeding e Integrazione con Azure AI

Per simulare un carico realistico e verificare il funzionamento dei servizi di Natural Language Processing (NLP), è stato impiegato il dataset pubblico open-source:
- **Fonte:** [Italian TripAdvisor Dataset (Kaggle)](https://www.kaggle.com/datasets/alessandrolobello/italian-tripadvisor) contenente recensioni in lingua italiana.
- **Adattamento (`DbSeeder.cs`):**
    - Il volume dei commenti è stato calibrato a un massimo di **150 record** (`MAX_COMMENTS_TO_SEED = 150).
    - Questo dimensionamento garantisce tempi di caricamento istantanei sul database Azure SQL, mantenendo comunque un campione eterogeneo per testare algoritmi e filtri.
    - È stata integrata la libreria **Bogus** per generare in modo riproducibile (`Randomizer.Seed = 42`) 50 dipendenti realistici, 8 categorie tematiche, 150 articoli, preferenze, follow, like e visualizzazioni.

È stato aggiunto al progetto il pacchetto ufficiale per l'analisi del linguaggio naturale:

```
dotnet add package Azure.AI.TextAnalytics
```

Il servizio `SentimentService` interroga il client di Azure Cognitive Services:
- Assegna l'etichetta qualitativa del testo (`Positive`, `Neutral`, `Negative`, `Mixed`).
- Restituisce i punteggi di confidenza normalizzati (`PositiveScore`, `NeutralScore`, `NegativeScore`), memorizzati nel DB e visualizzati con badge cromatici nell'interfaccia di amministrazione.

## Procedura Operativa di Configurazione e Avvio

**1. Configurazione Segreti Utente (.NET Secret Manager)**

Per motivi di sicurezza, le chiavi API e gli endpoint dei servizi cognitivi non sono tracciati nel repository, ma configurati tramite Secret Manager locale:

```
# Inizializzazione dei Secret Utente
dotnet user-secrets init

# Configurazione credenziali Azure Cognitive Services
dotnet user-secrets set "AzureLanguage:Endpoint" "https://<TUO-SERVIZIO>.cognitiveservices.azure.com/"
dotnet user-secrets set "AzureLanguage:ApiKey" "<TUA_API_KEY>"
```

**2. Rigenerazione del Database e Avvio**

```
# Rimozione forzata del database esistente
dotnet ef database drop --force

# Creazione dello schema e applicazione delle migration
dotnet ef database update

# Compilazione ed esecuzione dell'applicazione
dotnet run
```

## Conclusioni

Le modifiche apportate hanno garantito:
1. **Stabilità applicativa assoluta:** Eliminati i crash dovuti a violazioni di concorrenza su `DbContext`.
2. **Reattività dell'interfaccia utente:** Le query aggregate e l'uso dei `CancellationToken` hanno ridotto il carico di banda e di memoria sul server.
3. **Integrazione cloud scalabile:** Configurazione modulare di Azure AI con archiviazione sicura dei segreti e pipeline di popolamento dati riproducibile per contesti di collaudo accademico.
